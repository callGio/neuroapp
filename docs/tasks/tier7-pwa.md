## 3. Service worker (`viewer/public/sw.js`), offline support
- Version constant at the top (e.g. `const VERSION = "2026-11-13.1"`); caches named with it; delete old caches on `activate`. Document in a comment that the version must be bumped on each deploy that changes shell files.
- **Precache on install** (small app shell only, a few MB at most): the four HTML pages, manifest, favicon, icons, `assets/brain-lateral.webp`, fonts, the vendored three.js files the pages actually import (check the import maps / imports), `content/*.json`, `atlas-manifest.json`. Use `cache: "reload"` when fetching for the precache. A single failed file must not brick the install silently: fail the install loudly (so the old worker stays) rather than caching a partial shell.
- **Do NOT precache the 54 MB of models.** Cache them at runtime, cache-first, in a separate cache that is NOT wiped on version bumps (name it by a models version, e.g. `gyrafold-models-v1`), so returning visitors never re-download them. After one full atlas load online, the atlas must work offline.
- **Fetch strategy:** only handle same-origin GET. Navigations/HTML: network-first with a short timeout (about 3 s) falling back to cache, so deploys show up immediately online. JSON content and manifest: stale-while-revalidate. Fonts, three.js, images, icons: cache-first. Models: cache-first as above. Honour Range requests safely (if a request has a Range header, just pass it to the network). Ignore query strings when matching pages that use them (`neuron.html?part=...`, `?from=atlas`) via `ignoreSearch` for navigations.
- Offline navigation to an uncached URL falls back to cached `index.html`.
- `skipWaiting` only when the page asks for it (message), and a small, quiet "New version available. Reload" toast is optional; if you add it, make it one shared tiny snippet, accessible (role="status"), dismissible, and consistent with the existing dark UI. If it adds clutter, skip it and simply let the new worker take over on next launch. The owner's UX rule: simple, never overwhelming.
- Registration: a tiny inline snippet on all four pages, after load, guarded by `'serviceWorker' in navigator` and only on https or localhost. Must not throw in file:// or in browsers without support.
- Storage: call `navigator.storage.persist()` only after the user has loaded the atlas (not on first paint), and ignore the result.

## 4. Install affordance and offline status

On iOS Safari (no prompt event), do not show a button; at most one short line of help text near the footer is fine ("On iPhone: Share, then Add to Home Screen"), only on iOS and not when standalone. Place the button near the existing hero buttons without crowding them; match existing button styles; min 44 px tap target.

- After the atlas finishes loading all models online for the first time, show nothing intrusive; a one-time quiet line in the existing status element such as "Saved for offline use" is enough.
